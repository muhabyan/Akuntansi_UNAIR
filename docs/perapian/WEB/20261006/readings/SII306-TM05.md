# SII306 TM05: Relational Databases and Enterprise Systems

REF: RPS-SIA, minggu 5 · Richardson, Chang & Smith, AIS 4e ISE · Ch. 6, pp. 236–281

INTRO: Rancangan data dari TM4 kini diwujudkan sebagai database relasional: tabel-tabel yang saling terhubung. Kita mulai dari transaksi toko, lalu belajar aturan tabel, contoh Steve's Stylin' Sunglasses, kueri SQL (Structured Query Language, bahasa untuk meminta data), dan ERP (Enterprise Resource Planning, sistem yang menghubungkan proses perusahaan).

OBJECTIVES: Menjelaskan database, DBMS (Database Management System atau perangkat lunak pengelola database), data dictionary, DBA, serta keunggulan model relasional Codd. | Menerapkan empat aturan tabel relasional: entity integrity, referential integrity, atomic value (1NF), dan order independence. | Membaca skema relasional Steve's Stylin' Sunglasses beserta PK/FK (kunci utama/kunci rujukan), linking table, dan form/subform. | Menyusun kueri SQL dengan SELECT, WHERE, INNER JOIN, ORDER BY, DISTINCT, GROUP BY, HAVING, dan fungsi agregat. | Menjelaskan modul SAP S/4HANA, manfaat dan risiko ERP, serta trade-off cloud ERP dibanding on-premise.

blocks[36] h2: 4. Enterprise Systems & ERP Architecture

blocks[37] p: **Enterprise Resource Planning (ERP)** adalah rangkaian perangkat lunak terintegrasi untuk mengelola dan mengoordinasikan seluruh sumber daya, informasi, dan fungsi bisnis organisasi dari satu database relasional pusat. ERP menggantikan sistem lama departemen yang terisolasi dengan satu repositori data yang terdiri atas **lebih dari 10,000 tabel relasional yang saling terhubung** (seperti pada SAP ERP). blocks[54] table: 
HEADERS: Common trap | Koreksi
ROWS: Primary key null melanggar entity integrity. | Field PK wajib memiliki constraint NOT NULL dan indeks unik.
Orphan record melanggar referential integrity. | Foreign key harus merujuk PK valid di tabel induk; batasi penghapusan induk yang masih dirujuk (cascade restriction).
Tertukar `WHERE` dan `HAVING`. | `WHERE` menyaring baris sebelum agregasi (mis. `WHERE Sale_Date >= '2026-01-01'`); `HAVING` menyaring kelompok setelah agregasi (mis. `HAVING SUM(Amount) > 500`).
Kolom non-agregat tidak dicantumkan di `GROUP BY`. | Setiap kolom di `SELECT` di luar fungsi agregat (`SUM`, `AVG`, dst.) WAJIB ada di `GROUP BY`.
